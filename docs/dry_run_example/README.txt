这是哪来的
======================================================================

一次**真实干运行**的落盘快照：机器人是合成世界（没有连过任何真机），
相机也是合成世界，但除了"电机 + 相机"这一层物理之外，其余全部是真跑的——
真的采集循环、真的相位切分、真的 RAW 落盘、真的离线角点识别、真的三层分析。

★ 这份快照是 **1.0.2** 时期重跑的，**与这一版的代码一致**。1.0.2 相比快照的
上一版（1.0.0 时期）多了这些内容，对照时别当成异常：

* ``events.jsonl`` 里多了**组边界**：``group_started`` / ``group_finished``
  成对出现，本趟共 4 组（静态基线、快速几何检查、预实验 J1、组A J1），
  每组开头各有一条 ``disk_checked（分组）``。默认配置没开分组流水线，
  所以组内**没有** ``group_processing`` / ``raw_deleted``——那要打开
  ``paths.delete_raw_after_process`` 才有。
* ``capture_metadata.json`` 多了 ``source_size`` / ``cropped_size``；
  到位预览和棋盘格检查多落了 ``roi_checks/*.png`` 和 ``roi_checked`` 事件。
* ``events.jsonl`` 里还可能出现 ``settle_timeout`` / ``raw_kept`` 这类事件。
* 新增 ``vision/metrics.csv``（全趟逐帧几何一张表）与 ``vision/corners/*.csv``
  （每段一张角点表，6 位小数）、每段一份 ``segment_vision.json``
  （逐帧质心/转角/尺度/r_rms）。这三样是"边采边清删掉 RAW 之后还能复算"的依据。
* J6 的面内位移改用"质心位移 ⊕ 转动弧弦长"合成，轴线仍然是去质心后的
  二维 Kabsch。本趟只跑了 J1，所以这个变化在这份快照里看不到。

怎么复现
======================================================================

    run_dry_run_example.bat

等价的命令行（在工程根目录，PYTHONPATH=src）：

    python -m sj_pretest.cli dry-run \
        --stamp dryrun_example \
        --joints J1 --amplitudes 0.01,0.05,0.2 --repeats 2 \
        --formal-joints J1 --formal-step 0.05 --group A --stride 8

跑完大约两分钟；本目录是那份结果的**删减快照**，不是全量数据。

这一趟做了什么
======================================================================

* 到位过程：6 个中间点，每一步都问过一次确认（干运行里机器人一开始就在
  名义位姿，所以这 6 步的位移都是 0——见「这趟的已知局限」）。
* 静态基线：配置里的 15 s（干运行被 dry_run.shorten_durations 缩到 3 s）。
* 三档微动预实验：J1，幅度 0.01 / 0.05 / 0.2°，每个幅度正负各 2 次，
  每次从名义位姿独立出发（不累计），共 12 次动作 + 各自的回程。
* 离线分析：三层判据 + 步长推荐。
* 组A 正式实验：J1、步长 0.05°（这一趟是照命令行走的，不是照推荐值）。

关键数字（本次运行的输出，不是承诺值）
======================================================================

* 静态基线：50 帧 / 1.32 s，有效角点帧 100%；质心噪声 σx = 0.5326 px，
  σy = 0.5717 px，径向 0.4033 px；二维转角噪声 σ = 0.05613°。
* J1 的局部图像方向：6.0°，由 0.2° 档正负两组位移分别标定，
  正负夹角 172.1°（越接近 180° 越可信）；理论预测 −0.0°。
* 步长推荐：J1 → 0.2°（候选幅度里最小的、全部判据都通过的一档）。
  J2–J6 这一趟没跑预实验，所以没有推荐值——这是配置决定的，不是失败。
* 整场估算（ROI 800×600、6 关节、组A+组B、0.2° 步长、真机帧率 132.23 fps）：
  录制约 60 分钟，整场 RAW 约 233 GB；**打开分组流水线后盘上峰值只有
  最大那一组约 22.4 GB**（950×800 时约 35.5 GB）。满幅不裁 ROI 时整场约 1 TB、
  单组约 99 GB，会被 50 GB 硬上限直接拒绝。

这趟的已知局限（别把它的结论当科研结论）
======================================================================

1. **数据是合成的**。合成世界渲染的是真棋盘格图，离线识别也是真跑，但
   位移/振动是从合成世界的几何算出来的，不是真实机械臂的物理响应。
   所以这份报告里的数字能证明"链路是通的、判据是活的"，
   **不能**用来判断真机上哪一档幅度够用。
2. **到位过程是 6 步零位移**。干运行里机器人一开始就在名义位姿上，
   所以"相对当前位姿"的增量全为 0，标签会明说"不需要移动"。
   真机上这几步是真的要走的。
3. **合成棋盘格只有 16 px/格**，J6 的 0.2° 快速确认在干运行下可能报
   "看不出来"——这是分辨率不够，不是代码坏了。真机用的是 3 mm 小格、
   约 675 mm 工作距离，角点定位精度不在这一个量级上。

真机注意事项（照抄 START_HERE.md）
======================================================================

* collision_status 永远是 unknown：理论上限检查 ≠ 碰撞安全。
* 每一步运动都要人工确认；中途可以随时中止，中止后不会自动回位。
* 上位机磁盘：按 ROI 800×600 估，整场 233 GB；不裁 ROI 是约 1 TB。
  打开分组流水线后盘上峰值降到"最大那一组"（800×600 约 22.4 GB，
  950×800 约 35.5 GB）。任何一组的估算超过 50 GB 硬上限、或可用空间不够，
  工具会在**那一组开始之前**拒绝开始，而不是跑一半写满。
* 真机参数（IP、相机序列号、MVS 导入路径、ROI、曝光/增益、三档幅度、
  六个正式步长）在界面的参数面板里填，改完存进 configs\local_site.json。
