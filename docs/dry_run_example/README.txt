这是哪来的
======================================================================

一次**真实干运行**的落盘快照：机器人是合成世界（没有连过任何真机），
相机也是合成世界，但除了"电机 + 相机"这一层物理之外，其余全部是真跑的——
真的采集循环、真的相位切分、真的 RAW 落盘、真的离线角点识别、真的三层分析。

★ 这份快照是 **1.0.3** 时期重跑的，**与这一版的代码一致**。1.0.3 同比多了
这些内容，对照时别当成异常：

* **多了 `connection_check/` 一棵树**：连上设备后、任何运动命令之前，
  先采 5 s 整幅 RAW 量五件事（实际分辨率 / 实际帧率 / 帧号连续性 /
  实际 RAW 字节数 / 实际写盘速度）。通过之后测试 RAW 会被删掉，
  只留汇总与样本图——所以这里看到的就是"删完之后应该剩下什么"。
  干运行的分辨率是合成的 480×360，**不是**真机满幅 1936×1096。
* **默认配置现在开着"分组处理并删除 RAW"**（`delete_raw_after_process=true`），
  所以这份快照里有真正的 `group_processing` / `rtde_recorder_paused` /
  `raw_deleted` / `rtde_recorder_resumed` / `camera_resumed` 事件；
  段里的 `segment_vision.json` 写的是 `raw_available=false`。
* **组边界变了**：快速几何检查**六轴合为一组**；正式实验是**每一遍 repeat
  单独一组**（这一趟只跑了一遍，所以只有一个"组A J1 第1遍"）。
* `capture_metadata.json` 里 `source_size` 与 `raw_size` 应当**相等**
  （RAW 一律整幅），`analysis_roi` / `roi_origin` 说明离线分析窗口在哪、
  `corners_frame` 说明角点坐标口径（固定 `full_image`）。
* 报告里"静态基线"那一行现在写的是**本段录了多久**（采集口径，2.99 s），
  不再是离线处理的 wall clock；处理耗时单独一个字段 `process_seconds`。

怎么复现
======================================================================

    run_dry_run_example.bat

等价的命令行（在工程根目录，PYTHONPATH=src）：

    python -m sj_pretest.cli dry-run \
        --stamp dryrun_example \
        --joints J1 --amplitudes 0.01,0.05,0.2 --repeats 2 \
        --formal-joints J1 --formal-step 0.05 --group A --stride 8

跑完大约两分钟；本目录是那份结果的**删减快照**，不是全量数据。
快照由 `refresh_dry_run_snapshot.py` 从 run 目录里挑文件重做，
不是手工拷贝——避免"这次漏抄一个文件"。

这一趟做了什么
======================================================================

* **5 s 全屏采集检查**：合成相机 480×360 @ 132.23 fps，采到 662 帧、缺 0 帧，
  写盘 45.6 MB/s，结论"通过"，测试 RAW 已删除。
* 到位过程：6 个中间点，每一步都问过一次确认（干运行里机器人一开始就在
  名义位姿，所以这 6 步的位移都是 0——见「这趟的已知局限」）。
* 静态基线：配置里的 15 s（干运行被 dry_run.shorten_durations 缩到 3 s）。
* 三档微动预实验：J1，幅度 0.01 / 0.05 / 0.2°，每个幅度正负各 2 次，
  每次从名义位姿独立出发（不累计），共 12 次动作 + 各自的回程。
* 离线分析：三层判据 + 步长推荐。
* 组A 正式实验：J1、步长 0.05°，**一遍 repeat**（干运行把 3 遍缩成 1 遍，
  把 5 级阶梯缩成 2 级，为的是两分钟能跑完）。

关键数字（本次运行的输出，不是承诺值）
======================================================================

* 静态基线：本段录了 397 帧 / 2.99 s；参与统计 50 帧（`--stride 8` 抽样），
  有效角点帧 100%；质心噪声 σx = 0.5563 px，σy = 0.4270 px，
  径向 0.4645 px；二维转角噪声 σ = 0.02883°（离线处理这段花了 14.2 s，
  这个数只用来估"现场等多久"，不是实验量）。
* J1 的局部图像方向：359.3°，由 0.2° 档正负两组位移分别标定，
  正负夹角 178.3°（越接近 180° 越可信）；理论预测 −0.0°。
* 步长推荐：J1 → 0.2°（候选幅度里最小的、全部判据都通过的一档）。
  J2–J6 这一趟没跑预实验，所以没有推荐值——这是配置决定的，不是失败。
* 各组的磁盘估算（这一趟是合成尺寸，所以很小；真机满幅的数字看 README）：
  静态基线 0.06 / 峰值 0.08 GB、快速几何检查 0.15 / 0.18 GB、
  预实验 J1 0.72 / 0.87 GB、组A J1 第1遍 0.20 / 0.25 GB。
  四条 `disk_checked` 的 ok 都是 true；每一组的峰值都低于当时的硬上限。
* RTDE 暂停/恢复成对出现，且两侧行数**相等**（403/403、797/797、3161/3161、
  3608/3608）——相等就证明确实是"暂停"而不是"另开一段"。

没有放进来的
======================================================================

* 所有 RAW 帧文件（frames.raw）：一趟几百 MB，纯二进制，放进来没有意义。
  采集格式、缺帧记账、相位窗口这些"怎么落盘"的证据在 capture_summary.txt
  和 events.jsonl 里都有。
* robot_states.csv 除前 200 行以外的内容（见上）。
* 其余各段采集的样本帧、其余角点 CSV、其余 ROI 检查图：每类留一个样例即可，
  凑齐了只是占地方（角点 CSV 单张就有几百 KB）。

这趟的已知局限（别把它的结论当科研结论）
======================================================================

1. **数据是合成的**。合成世界渲染的是真棋盘格图，离线识别也是真跑，但
   位移/振动是从合成世界的几何算出来的，不是真实机械臂的物理响应。
   所以这份报告里的数字能证明"链路是通的、判据是活的"，
   **不能**用来判断真机上哪一档幅度够用。
2. **5 s 采集检查量到的是合成相机**（480×360、合成帧率）。它证明这条链路
   跑得通、会删测试 RAW、会重算分组峰值，但**不等于**验证过真机的海康相机
   和真实写盘速度。真机上的五项实测值以真机跑出来的那份
   `connection_check/connection_check.txt` 为准。
3. **到位过程是 6 步零位移**。干运行里机器人一开始就在名义位姿上，
   所以"相对当前位姿"的增量全为 0，标签会明说"不需要移动"。
   真机上这几步是真的要走的。
4. **合成棋盘格只有 16 px/格**，J6 的 0.2° 快速确认在干运行下可能报
   "看不出来"——这是分辨率不够，不是代码坏了。而且 J6 在合成尺度下接近
   可分辨极限，同样的配置重跑有时判"以面内为主"、有时判"看不出来"。
   真机用的是 3 mm 小格、约 675 mm 工作距离，角点定位精度不在这一个量级上。

真机注意事项（照抄 START_HERE.md）
======================================================================

* collision_status 永远是 unknown：理论上限检查 ≠ 碰撞安全。
* 每一步运动都要人工确认；中途可以随时中止，中止后不会自动回位。
* **连上设备后先过 5 s 全屏采集检查**，不通过就一步都不走。
* 默认开着"分组处理并删除 RAW"：盘上任何时刻只有当前一组的 RAW，
  真机满幅下的最坏一组是正式组B 的一遍 repeat（Δ=0.2° 时峰值 38.49 GB）。
  任何一组的估算峰值超过 50 GB 硬上限时，工具会在**那一组开始之前**拒绝开始，
  而不是跑一半写满；单遍太大时只在"已经回到名义姿态"处再拆一级。
* **RAW 一律整幅**，`camera.analysis_roi` 只决定离线去哪里找角点，不改变
  RAW 尺寸、也不参与磁盘估算。
* 真机参数（IP、相机序列号、MVS 导入路径、离线分析 ROI、曝光/增益、
  三档幅度、六个正式步长）在界面的参数面板里填，改完存进 configs\local_site.json。
